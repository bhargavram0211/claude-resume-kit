# Bundle: FullStack/SWE/Backend

**For:** Software Engineer, Backend Engineer, Full Stack Engineer, Senior Engineer, Staff Engineer (IC track)

**Companies:** Startups (Series A-C), FAANG (Facebook, Amazon, Apple, Netflix, Google), Discord, Stripe, Airbnb, Uber (engineering-focused roles)

---

## Section 1: Role Profile

**What FullStack/SWE roles value:**

1. **Shipping Impact** — Can you take an idea to users? Do you ship fast and iterate?
2. **System Design** — Can you architect APIs, databases, caching strategies? Do you think about scale?
3. **Technical Depth** — Do you understand how pieces work together? Can you debug down to the OS layer?
4. **Ownership** — Do you own features end-to-end? Can you unblock yourself?
5. **Collaboration** — Can you work with product, design, ops? Do you communicate well?

**Resume framing for this persona:**
- Lead with user impact: "50k users," "shipped in 4 weeks," "grew engagement 18%"
- Emphasize shipping velocity: "Owned full-stack feature," "End-to-end design and implementation"
- Show technical decision-making: "Built caching layer reducing latency 40%," "Designed microservice for payment processing"
- Name modern tech: React, TypeScript, Python, Node.js, PostgreSQL, Kubernetes (if relevant), etc.

**Positioning against DevOps/SRE candidates:**
- You're "features" (user-facing, product impact) not "plumbing" (infrastructure)
- You care about shipping over infrastructure elegance
- This is not lesser — it's a different lens on building products
- SWE hiring managers care more about "can you ship?" than "can you scale this to 1M RPS?"

## Section 2: Summary Guide

**Tagline pattern:** `[Backend/Full Stack] Engineer | [Primary Tech Stack] | [Product/Technical Impact]`

**Examples:**
- "Full Stack Engineer | React + Node.js | Shipped 5 features to 50k users, 18% engagement increase"
- "Backend Engineer | Python + PostgreSQL | Built payment system handling $1M+/day in transactions"
- "Software Engineer | Microservices Architecture | Designed system scaling to 1M daily active users"

**Building blocks (pick 2-3 per JD):**
- "Shipped..." + [feature/system] + [user impact: users, DAU, revenue impact]
- "Built..." + [technical: API, service, database, frontend] + [scale: throughput, latency, users]
- "Designed..." + [architecture: microservice, caching layer, auth system] + [impact: enabled X or reduced Y]
- "Owned full-stack..." + [feature/system] + [timeline: "in 4 weeks"]

**Metrics that impress SWE hiring managers:**
- User/product metrics (50k users, 18% engagement increase, $1M+ revenue)
- Shipping velocity (shipped feature in 2 weeks, 5+ features in quarter)
- Technical metrics (reduced latency 40%, API response <200ms, 99.9% uptime)
- Scale (1M+ DAU, 1M+ RPS, handling $1B+ transactions annually)
- Ownership signal ("owned full-stack," "from design to shipping," "end-to-end")

## Section 3: Achievement Reframing Map

**For each achievement, determine the FullStack/SWE angle:**

| Achievement | SWE Angle | Headline Verb | Product Signal | Example Reframed Bullet |
|-------------|-----------|---------------|----------------|------------------------|
| Shipped latency optimization | Improved user experience | "Built" or "Shipped" | users affected, latency reduction | "Shipped latency optimization improving checkout load time 40% for 500k users" |
| Built authentication system | Enabled product expansion | "Designed" + "Shipped" | security + user trust | "Designed OAuth + JWT auth system securing 100k+ user accounts; shipped in 3 weeks" |
| Mentored junior engineer | Built team capability | "Mentored" + "shipped" | team impact + feature shipped | "Mentored engineer through system design; they shipped payment integration independently" |
| Fixed critical bug | Improved reliability | "Debugged" + "fixed" | user impact | "Debugged race condition in checkout; fixed 95% of failed transactions affecting $50k/day revenue" |
| Optimized database | Reduced infrastructure costs | "Optimized" | cost savings + scaling | "Optimized database queries reducing load 60%; enabled 10x scaling without new infrastructure" |
| Built caching layer | Improved UX at scale | "Built" or "Implemented" | latency + users | "Implemented Redis caching layer reducing API latency 70% for 100M+ daily requests" |

**Reframing heuristics:**
- Product first: always mention user impact, engagement, or revenue
- Technology second: mention tech choices but in service of user experience
- Ownership: "Owned," "Shipped," "Built end-to-end" — signal autonomy
- Shipping velocity: timelines matter (4 weeks, shipped in sprint)
- Scale awareness: users, DAU, RPS — but only if it's part of your achievement

## Section 4: Skills Guide — FullStack/SWE Emphasis

**Group 1: Backend & APIs**
- Python (Django, FastAPI, Flask)
- Node.js (Express, Nest.js)
- Go (Gin, gRPC)
- Java (Spring Boot)
- TypeScript (full-stack or backend-focused)
- REST API design, GraphQL, Protocol Buffers
- Microservices architecture

**Group 2: Frontend & Web**
- React (hooks, state management, testing)
- TypeScript (for frontend type safety)
- HTML / CSS (semantic markup, responsive design)
- Testing (Jest, React Testing Library, Cypress)
- Web performance (bundle optimization, lazy loading, caching)

**Group 3: Databases & Data Layer**
- PostgreSQL (ACID, query optimization, indexing)
- MySQL (similar to PostgreSQL)
- MongoDB (document model, scaling)
- Redis (caching, data structures, pub/sub)
- Elasticsearch (full-text search, analytics)
- API design (pagination, filtering, N+1 query prevention)

**Group 4: Tools & DevOps (practical for engineers)**
- Git workflows (branching, PR reviews, rebasing)
- Docker (containerization, multi-stage builds)
- Testing frameworks (unit, integration, e2e)
- CI/CD understanding (GitHub Actions, GitLab CI)
- Debugging tools (browser devtools, logging, profiling)
- Cloud platforms (AWS, GCP, Heroku — as deployment targets)

**Languages (if not in above groups):**
- JavaScript / ES6+ (modern syntax, async/await)
- SQL (query optimization, understanding databases)
- Bash (scripting, devops understanding)

**When generating resume for FullStack/SWE:**
- Bold: languages and frameworks mentioned in JD (React, TypeScript, Python, PostgreSQL, etc.)
- Group order: lead with most JD-relevant (Backend for backend-focused roles, Frontend for full-stack, etc.)
- Example: if JD emphasizes "React + Node.js full-stack," lead with Frontend, then Backend
- Include modern, product-shipping tools; de-emphasize pure infrastructure

## Section 5: Cover Letter Guide

**Paragraph 1 (HOOK) — 2-3 sentences:**
- Open with their product or engineering challenge (not generic company praise)
- Example: "I saw you're building [feature/product]. I shipped something similar at [company] that reached [users]."
- Reference their blog post, engineering talk, or public code if possible
- Accessible language here — recruiting team reads first, then engineering

**Paragraph 2 (EVIDENCE) — 3-5 sentences:**
- Pick 2-3 achievements showing shipping velocity + technical depth
- Lead with product/user impact, back it up with technical decisions
- Example: "I shipped an end-to-end payment system at [company] handling $1M+/day in transactions. Built with [tech stack]; reduced fraud via [technical approach]."
- Show you think about tradeoffs: "Chose [tech] because [reason]"

**Paragraph 3 (FORWARD MOMENTUM) — 2-3 sentences:**
- What excites you about shipping/building THIS product?
- What's a technical idea you'd explore (if you understand their product)?
- Example: "I'm excited about the growth opportunity for [service]. I'd love to explore how you're thinking about [scaling/feature expansion/reliability]."

**Paragraph 4 (CLOSING) — 1-2 sentences:**
- Direct call to action: "I'm keen to discuss how my experience shipping [similar achievement] can help [team goal]."
- Optional: "Happy to pair on a quick architecture problem if that's helpful."

**Jargon level:** Balanced — use technical terms (PostgreSQL, Redis, microservice) but explain implications for users (improved latency = better UX = higher retention).

**Tone:** Enthusiastic about building products, not just writing code. "I love shipping features" not "I love programming languages."
